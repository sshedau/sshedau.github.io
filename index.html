E-Commerce Microservices Backend

Java, Spring Boot, Spring Cloud, Spring Security, PostgreSQL, Redis, Docker

An online-store backend split into independent services instead of one monolith, so each domain owns its code and its data.

  • User, Product and Order microservices, each with its own PostgreSQL database.
  • API Gateway routing, with JWT authentication and role-based access control (RBAC) in Spring Security.
  • REST APIs with CRUD, pagination, sorting and search; OpenFeign for inter-service calls.
  • Redis caching, containerised with Docker, deployed on Render with Neon PostgreSQL and Upstash Redis.
  1. API Gatewayroutes requests, JWT and RBAC checks
  2. User serviceown PostgreSQL database
  3. Product serviceown PostgreSQL database, Redis cache
  4. Order serviceown PostgreSQL database, calls other services via OpenFeign

Most of the learning was in the seams: keeping databases isolated while services still need each other’s data, and debugging deployment and caching problems on free-tier hosting.

AI-Powered Fitness Microservices Backend

Java, Spring Boot, Spring Cloud, PostgreSQL, MongoDB, RabbitMQ, Google Gemini API

A fitness-tracking backend that turns logged activities into personalised recommendations without making the user wait on an AI call.

  • User, Activity and AI Recommendation microservices.
  • Eureka for service discovery and Config Server for centralised configuration.
  • Spring Cloud API Gateway in front of the services; WebClient for inter-service communication.
  • REST APIs backed by PostgreSQL and MongoDB.
  • RabbitMQ for asynchronous processing; Google Gemini API generates the recommendations.
  1. API Gatewaysingle entry point
  2. User and Activity servicesREST APIs on PostgreSQL and MongoDB
  3. RabbitMQasynchronous hand-off
  4. AI Recommendation servicecalls the Google Gemini API

Recommendation generation is decoupled from the request path through a message queue, which is the part of this project I enjoyed designing most.

Delivery Management System

Java, OOP, Design Patterns

A logistics dispatch simulation, built to practise object-oriented design on a problem with real moving parts.

  • Dynamic delivery assignment based on distance, ratings and delivery zones.
